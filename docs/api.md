## Documents

### List Documents

```http
GET /api/v1/documents/
```

Example:

```bash
curl http://localhost:8000/api/v1/documents/
```

List responses intentionally omit full extracted document text.

### Upload Document

```http
POST /api/v1/documents/
```

Content type:

```text
multipart/form-data
```

Example:

```bash
curl -X POST \
  http://localhost:8000/api/v1/documents/ \
  -F "title=Student Guide" \
  -F "file=@sample_data/northbridge_student_guide.docx"
```

Only `.docx` files are accepted.

A successful upload automatically runs:

```text
extraction
chunking
embedding
indexing
```

Example fields returned:

```json
{
  "id": 1,
  "title": "Student Guide",
  "original_filename": "northbridge_student_guide.docx",
  "text_content": "...",
  "status": "indexed",
  "processing_error": "",
  "chunk_count": 3
}
```

### Retrieve Document

```http
GET /api/v1/documents/{id}/
```

Example:

```bash
curl http://localhost:8000/api/v1/documents/1/
```

The detail endpoint includes the complete extracted `text_content`.

### Partial Update

```http
PATCH /api/v1/documents/{id}/
```

Title-only example:

```bash
curl -X PATCH \
  http://localhost:8000/api/v1/documents/1/ \
  -H "Content-Type: application/json" \
  -d '{
    "title": "Updated Student Guide"
  }'
```

A metadata-only change does not rerun indexing.

Replacing the file does rerun processing and indexing.

### Delete Document

```http
DELETE /api/v1/documents/{id}/
```

Example:

```bash
curl -X DELETE \
  http://localhost:8000/api/v1/documents/1/
```

Successful response:

```text
204 No Content
```

## Ask a Question

```http
POST /api/v1/questions/ask/
```

Example request:

```bash
curl -X POST \
  http://localhost:8000/api/v1/questions/ask/ \
  -H "Content-Type: application/json" \
  -d '{
    "question": "How much is the late tuition payment fee?",
    "document_ids": [1],
    "top_k": 3,
    "min_similarity": 0.2
  }'
```

Fields:

| Field | Required | Description |
| --- | --- | --- |
| `question` | yes | User question |
| `document_ids` | no | Indexed documents to search |
| `top_k` | no | Maximum retrieved chunks, default 5 |
| `min_similarity` | no | Similarity threshold, default 0.2 |

`document_ids` behavior:

```text
omitted     -> search all indexed documents
null        -> search all indexed documents
[]          -> search all indexed documents
[1, 2]      -> search only selected indexed documents
```

Example response:

```json
{
  "id": 10,
  "question": "How much is the late tuition payment fee?",
  "answer": "The late tuition payment fee is 25 US dollars.",
  "top_k": 3,
  "min_similarity": 0.2,
  "document_ids": [
    1
  ],
  "sources": [
    {
      "id": 20,
      "chunk_id": 7,
      "document_id_snapshot": 1,
      "document_title": "Northbridge University Student Services Guide",
      "chunk_index": 2,
      "similarity": 0.4,
      "created_at": "..."
    }
  ],
  "created_at": "..."
}
```

The exact answer wording may vary because it is generated by an LLM.

## No-Context Response

If no chunk satisfies the retrieval threshold, the LLM is not called.

English example:

```json
{
  "question": "Who is the university president?",
  "answer": "The available documents do not contain enough information to answer this question.",
  "sources": []
}
```

The record is still stored in question-answer history.

## Question History

### List

```http
GET /api/v1/questions/
```

Example:

```bash
curl \
  "http://localhost:8000/api/v1/questions/?page=1&page_size=10"
```

Response:

```json
{
  "count": 15,
  "next": "http://localhost:8000/api/v1/questions/?page=2&page_size=10",
  "previous": null,
  "results": []
}
```

Defaults:

```text
page size: 20
maximum page size: 100
```

History is ordered from newest to oldest.

### Detail

```http
GET /api/v1/questions/{id}/
```

Example:

```bash
curl http://localhost:8000/api/v1/questions/10/
```

Detail responses include source snapshots.

History endpoints are read-only.

  "status": "ok",

## Validation Errors

Example:

```bash
curl -X POST \
  http://localhost:8000/api/v1/questions/ask/ \
  -H "Content-Type: application/json" \
  -d '{
    "question": ""
  }'
```

Response:

```json
{
  "error": {
    "code": "validation_error",
    "message": "Request validation failed.",
    "details": {
      "question": [
        "This field may not be blank."
      ]
    }
  }
}
```

## Invalid Document Selection

A question may only reference existing indexed documents.

Example error:

```json
{
  "error": {
    "code": "validation_error",
    "message": "Request validation failed.",
    "details": {
      "document_ids": [
        "All selected documents must exist and be indexed. Invalid document IDs: [999999]"
      ]
    }
  }
}
```

## 404 Errors

Example:

```bash
curl http://localhost:8000/api/v1/documents/999999/
```

Response:

```json
{
  "error": {
    "code": "not_found",
    "message": "No Document matches the given query."
  }
}
```

## Service Failure

Retrieval or LLM failures are exposed as:

```text
HTTP 503 Service Unavailable
```

Response format:

```json
{
  "error": {
    "code": "service_unavailable",
    "message": "..."
  }
}
```

## Swagger

Open:

```text
http://localhost:8000/api/docs/
```

Swagger supports interactive execution of the API.

For document upload, use the multipart file selector.

For question answering, use:

```json
{
  "question": "Where is the IT Help Desk located?",
  "document_ids": [
    1
  ],
  "top_k": 3,
  "min_similarity": 0.2
}
```

## ReDoc

Open:

```text
http://localhost:8000/api/redoc/
```

ReDoc provides a readable API reference generated from the same schema.

## OpenAPI Validation

Regenerate and validate the committed API schema with:

```bash
docker compose exec web python manage.py spectacular \
  --file docs/openapi-schema.yml \
  --validate
```
